# ТЗ: анализ аудиоклипов v1 (`analyze_audio_clip`, `compare_audio_regions`)

Статус: к реализации **после** `ho_mcp_server_v1.md` (встаёт в тот же сервер).
Исполнитель: агент `deepseek`. Ревью: архитектор + владелец.
Обязательно прочитать: `docs/LISTENING_LOOP.md` — зачем это всё.

## 0. Цель и границы

Дать модели посчитанные признаки звучащего фрагмента аудиоклипа и **разницу признаков между двумя
фрагментами**, чтобы она могла привязать слова человека («мутно», «бас тонет») к данным.
Типичный сценарий: человек делает Bounce нужного куска и говорит «послушай трек N, такты 5–8».

**В скоупе:**
- `agents/agents/audio_features.py` — детерминированные признаки по массиву сэмплов (только numpy);
- `agents/agents/audio_source.py` — область клипа в долях → отрезок файла в секундах → сэмплы;
- два инструмента в `agents/agents/mcp_server.py`;
- зависимость `soundfile` (WAV/AIFF/FLAC). numpy уже есть транзитивно через music21 — сделать явной.

**Вне скоупа (не делать):**
- автоматический рендер/запись (никаких `record_section`, транспорта, создания треков) — сервер read-only;
- описание аудио-моделью, тональность/аккорды из аудио, разделение источников;
- librosa, essentia, scipy и прочие тяжёлые зависимости — только numpy + soundfile;
- пороги-«оценки» («слишком мутно»): признаки и разницы, без вердиктов;
- изменения ритм/гармония-пайплайнов и их моделей.

## 1. Данные от моста

`get_clip_info(track_index, clip_index)` для аудиоклипа (проверено по исходникам моста 1.8.1) отдаёт
сверх общих полей: `file_path`, `warping`, `warp_markers: [{beat_time, sample_time}]`,
`loop_start`, `loop_end`, `start_marker`, `end_marker`, `looping`.
Добавить `get_clip_info` для аудио в рабочие сценарии; белый список команд не расширять.

## 2. Область → секунды (`audio_source.py`)

```python
class AudioRegion(BaseModel):
    track_index: int; clip_index: int
    start_beat: float | None = None   # в долях клипа; None → loop_start (или start_marker, если не looping)
    end_beat: float | None = None     # None → loop_end (или end_marker)

def load_region(bridge, region: AudioRegion) -> tuple[np.ndarray, int, RegionContext]: ...
```
- `RegionContext`: имена трека/клипа, `file_path`, `sample_rate`, `channels`, `warping`,
  `start_beat`, `end_beat`, `start_sec`, `end_sec`, `tempo_bpm`, `beats_per_bar`, `mapping` ("warp_markers"|"tempo"|"seconds").
- **warping=True:** доли → секунды файла кусочно-линейно по `warp_markers` (`beat_time` → `sample_time`,
  `sample_time` — секунды файла). Вне крайних маркеров — экстраполяция наклоном крайнего сегмента.
  Меньше 2 маркеров → по темпу сета от `sample_time` единственного маркера (или от 0).
- **warping=False:** считать, что `loop_*`/`*_marker` уже в секундах файла (`mapping="seconds"`).
  **Это допущение по документации LOM — архитектор проверит на живом Live; в коде пометить комментарием.**
  Перевод секунд в доли (для онсетов и тактов) — по темпу сета: `beats = sec * tempo / 60`.
  `start_beat`/`end_beat`, заданные пользователем для unwarped-клипа, тоже переводятся по темпу.
- Читать только нужный отрезок (`soundfile.read(start=…, stop=…)`), не весь файл.
- Файл не найден / не аудио / пустой отрезок → понятная ошибка в `errors`, без падения сервера.
- Многоканальное → сохраняем каналы для стерео-признаков; моно-сумма для остальных.

## 3. Признаки (`audio_features.py`, только numpy)

Все уровни в dBFS, частоты в Гц. Окно анализа: Hann, 2048, hop 512 (константы в `AudioFeatureConfig`).

**Уровень:** `rms_db`, `peak_db`, `crest_db` (= peak − rms).
**Спектр (по усреднённому спектру мощности):**
- `band_share_db`: доля энергии по полосам, в дБ относительно общей:
  `sub` <60, `low` 60–250, `low_mid` 250–500, `mid` 500–2000, `high_mid` 2000–6000, `high` 6000–Найквист;
- `centroid_hz`, `rolloff85_hz`, `flatness` (геом./арифм. среднее мощности, 0..1).
**Стерео (если 2 канала):** `lr_correlation` (−1..1), `side_to_mid_db`.
**Онсеты:** spectral flux (полуволновое выпрямление, сумма по бинам) → нормализация → пик-пикинг
(локальный максимум, порог = медиана + `k`·MAD, минимальная дистанция 50 мс; параметры в конфиге).
Время онсетов переводится обратно в доли клипа (обратное отображение из раздела 2).
`onsets_beats`, `onset_count`, `onset_density_per_bar`.
**Ритм онсетов:** онсеты → `Note` (pitch C3, velocity 100) → `run_deterministic_rhythm_analysis`
с `material="pitched"` и `clip_length_beats` = длина области. В ответ — его компактный вид
(как в `analyze_clip`). Так аудио получает те же `CYCLE`/`LOOSE`/`SWING_8TH`, что и MIDI.
**Во времени:** `per_bar`: для каждого такта области — `rms_db`, `centroid_hz`, `band_share_db`
(неполный последний такт — помечать `partial: true`).

## 4. Инструменты MCP

### 4.1 `analyze_audio_clip(track_index, clip_index, start_beat=None, end_beat=None, detail=False)`
`{"context": RegionContext, "features": {...}, "onset_rhythm": {...} | null, "errors": {...}}`.
Компактно (`detail=False`): без `onsets_beats` и без `per_bar` длиннее 32 тактов (тогда агрегировать
по 4 такта и указать `per_bar_step: 4`). Цель — до ~4 КБ. Числа округлять до 2 знаков (Гц — до целых).

### 4.2 `compare_audio_regions(a: AudioRegion, b: AudioRegion)`
Считает признаки обеих областей и возвращает:
- `a`, `b` — компактные признаки (без онсет-ритма);
- `delta` — `b − a` для всех скалярных признаков и по каждой полосе `band_share_db`;
- `largest_differences` — топ-5 по детерминированному ранжированию: полосы и уровни по |Δ дБ|,
  `centroid_hz`/`rolloff85_hz` по |Δ| в октавах (`log2(b/a)`), `flatness`/`lr_correlation` по |Δ|×10.
  Каждый элемент: `feature`, `a`, `b`, `delta`, `unit`. Без слов-оценок.
- Области разной длины — допустимо (признаки нормированы); разный sample rate — допустимо.

## 5. Тесты (синтетика numpy → WAV через soundfile в `tmp_path`, фейковый мост из ТЗ сервера)

1. Синус 1 кГц, −6 dBFS peak → `peak_db≈−6` (±0.1), `rms_db≈−9.01` (±0.1), `crest_db≈3.01`; доминирует `mid`.
2. Синус 300 Гц → максимум `low_mid`; синус 80 Гц → максимум `low`.
3. Белый шум → `flatness` > 0.8; синус → `flatness` < 0.1.
4. Стерео: одинаковые каналы → `lr_correlation≈1`, `side_to_mid_db` < −60; противофаза → ≈ −1.
5. Щелчки (короткие импульсы) каждые 0.5 с при 120 BPM, warping=False → онсеты на 0,1,2… долях (±0.03);
   онсет-ритм даёт `CYCLE` period 1.0.
6. Warp: файл 2 с, маркеры `[{beat 0, sec 0}, {beat 4, sec 1.0}]` (т.е. 240 BPM в файле) →
   область `start_beat=2, end_beat=4` читает секунды 0.5–1.0.
7. Компаратор: A = синус 1 кГц, B = тот же + шум в 250–500 Гц → в `largest_differences` первым `low_mid`
   с Δ > 0; A vs A → все `delta≈0`.
8. `per_bar`: 3 такта, громкость растёт по тактам → `rms_db` возрастает; неполный такт помечен.
9. Ошибки: несуществующий `file_path`, MIDI-клип вместо аудио, пустая область → `errors`, без исключения наружу.
10. Компактный ответ на 16-тактовом файле < 4096 символов, без `onsets_beats`.

## 6. Критерии приёмки
- Все тесты `agents` зелёные, старые не изменены.
- Нет новых зависимостей кроме `soundfile` (+ явный `numpy`).
- Сервер по-прежнему не шлёт в мост ничего вне белого списка и ничего не пишет на диск.
- Отчёт по формату агента; допущение о единицах для unwarped-клипов вынесено в «Вопросы к ревью».
